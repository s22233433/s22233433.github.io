Release notes

Completed features, data sources, and privacy boundaries in one place. Versions v0.5.11–v0.5.22 strengthen passive social-link discovery, code efficiency, cross-platform analytical consistency, and local-data integrity.

Chrome Web Store public versionv0.5.16

Approved and available to install from the Chrome Web Store

Install from the Chrome Web Store ↗
Instagram social linksv0.5.222026.07

Passively identify and retain account social links

Already-loaded Instagram profile data can now supplement YouTube, Facebook, Threads, and TikTok links. The data remains local to the browser and adds no platform requests, permissions, or metric inputs.

  • Passively processes bio_links, Facebook Page IDs, and existing header/link-dialog anchors. Only matching HTTPS platform domains are accepted; Instagram redirect links are safely unwrapped and validated first.
  • Links merge across captures into the existing profile and account library, then appear beside the account in the Instagram panel, detailed report, and favorites page. Older cache and backups remain compatible.
  • Also reads already-loaded React props from the current profile’s Link button, narrowly allowing the link payload to fill the routed username even when that local object does not repeat a username or ID.
Code optimizationv0.5.212026.07

Shared analytics core, less cross-platform maintenance

Instagram and TikTok now reuse proven pure analytics logic, reducing duplicate code and missed cross-platform fixes. It adds no platform requests and does not change passive capture, local-only storage, or metric formulas.

  • KPI calculation, view selection, medians, daily engagement trends, multi-account comparison, date helpers, and panel geometry now use shared modules so a common fix applies consistently to both platforms.
  • Parsers, post merging, report scopes, snapshots, IndexedDB, exports, and pages remain platform-specific so Instagram and TikTok data semantics do not mix.
  • Data-flow, change-impact, and technical-debt records now mark the shared core and intentionally separate modules, reducing future maintenance and regression cost.
Local-data integrityv0.5.202026.07

Automatic image-cache cleanup and safer backup restore

Strengthens local media-cache and backup integrity without adding platform requests or changing passive capture and local-only processing boundaries.

  • After post-retention cleanup, account deletion, or snapshot deletion, it removes local image Blobs no longer referenced by posts, accounts, snapshots, or recommendation lists, preventing rotating short-lived CDN URLs from steadily consuming local storage.
  • Report, history, comparison, and favorites refresh their temporary local-image URLs after a cached image changes, while still falling back to the original HTTPS image URL when no Blob is available.
  • Backup restore now validates settings, Instagram, TikTok, and locale data before writing. If any part fails, the prior local data is restored. Settings also links to these release notes.
Local media and onboardingv0.5.192026.07

More reliable local images and precise account data

Improves local image storage, first-use guidance, and Instagram first-screen account summaries while preserving passive capture and local-only storage boundaries.

  • New images no longer write Base64. Loaded avatars and thumbnails are compressed to a 120px maximum side and stored as platform-local IndexedDB Blobs; report, history, comparison, and favorites prefer the local Blob and fall back to the platform HTTPS URL. Existing Base64 remains readable.
  • The Instagram panel adds five-step onboarding in Traditional Chinese, Simplified Chinese, and English: it appears automatically on first use, 💡 replays it, collapsed panels expand first, and ESC closes only the current display. Settings adds release-note links.
  • Improves exact follower_count, following, and media-count recovery from already-loaded React/Relay and hydration state. Abbreviated DOM values never override exact follower counts.
Panel and snapshot controlv0.5.182026.07

Wider controls and manual snapshots

Makes day-to-day analysis and snapshot saving more direct while keeping passive capture and local-only storage boundaries.

  • Instagram and TikTok panels widen from 372px to 416px. Instagram Compare and Favorite are independent actions beside the Analytics/Similar creators tabs, without adding panel height.
  • A persistent 💾 manual snapshot action sits between Stop and Report. It can save any non-empty local cache; background refresh still creates no snapshot.
  • Always snapshot saving no longer skips a later completed analysis only because aggregate values match. Repeated writes in the same analysis session remain blocked.
Local images and creator notesv0.5.172026.07

More reliable avatars, thumbnails, and local notes

Addresses temporary CDN image failures and background-refresh field updates while keeping new data in the browser.

  • Settings add default-on Base64 local storage for avatars and post thumbnails. Avatars are compressed to 80×80 and thumbnails to a maximum 80px side. Failed images fall back to an account initial and black images are not stored.
  • The panel adds a ✏️ creator note action. Favorite accounts can view, edit, and search notes, which remain in the existing backup/restore flow.
  • When background refresh observes an existing post again, likes, comments, views, and capture time update on that post instead of only adding new posts. It does not create snapshots.
Background refresh integrityv0.5.162026.07

Background-refresh data-integrity fix

Fixes an issue where Instagram profile and Reels pages loading in the background at the same time could let a smaller first-screen payload overwrite complete cache and reduce a report to 12 posts.

  • Moves existing-post reading, new-data merging, per-account limiting, and write-back into one IndexedDB transaction so the resulting cache is consistent after background refresh.
  • Partial profiles without an ID retain their stable account key, favorite state, and saved local avatar, then restore report metadata.
  • Background refresh updates current cache and report data only; it does not create historical snapshots.
Account and detail managementv0.5.152026.07

Favorite-account management and sortable per-post details

Local account and per-post data are easier to find, manage, and remove while the passive-observation and local-storage boundaries remain unchanged.

  • Favorite accounts support single deletion plus select-all or multi-select deletion of visible accounts. Deletion clears local cache, snapshots, comparison data, and Instagram recommendation lists only for that platform account.
  • Snapshot links display their snapshot count, while the account ID and name link directly to the corresponding platform profile.
  • Instagram and TikTok per-post report details add local first-capture time (yyyy-MM-dd HH) and sorting by publication date, type, likes, and views. Excel details retain capture time too.
Local data managementv0.5.142026.07

Complete local backup, favorite refresh, and report range control

Saved analysis data, refresh workflows, and the reporting scope are more complete while data stays processed locally in the browser.

  • Backup and restore now include normalized Instagram and TikTok post cache, analysis metadata, favorites, snapshots, comparisons, and Instagram recommendations, while remaining compatible with older backups.
  • “Refresh data” for a favorite account passively loads Instagram profile and Reels pages in the background, or a TikTok profile page; it only organizes first-screen data the platform normally loads. Full scrolling analysis remains manual.
  • Both reports add an eight-option analysis range below the data-information row, using four day and four post presets from Settings. Changing it updates only the eight KPI cards and engagement trend; the overview, top content, per-post details, and Excel retain their existing data sources.
Local datav0.5.132026.07

A local data-usage overview in Settings

The Data section now includes a read-only storage dashboard so you can see what the extension has saved and the approximate amount of local space it uses.

  • Shows estimated IndexedDB and chrome.storage.local usage, browser quota, and storage-entry count.
  • Separately counts Instagram and TikTok accounts, posts, snapshots, favorites, and comparisons; Instagram also shows recommendation records.
  • Refreshes manually and never writes, clears, or changes existing data while measuring.
Localizationv0.5.122026.07

Chrome-native extension localization

Chrome i18n metadata now supports Traditional Chinese, Simplified Chinese, and English. The extension name, description, and toolbar hint follow Chrome’s UI language while the in-extension language picker remains available.

Data precisionv0.5.112026.07

Keep and display exact follower counts

When an already-loaded Instagram response contains follower_count, the extension retains that exact integer. Visible DOM abbreviations such as “1.1K” can no longer overwrite it; the panel and report can show the full number.

Chrome Web Store public versionv0.5.102026.07

Passive capture fix for similar Instagram accounts

Instagram may return similar-account JSON as text/javascript. This release updates the existing response detection and, when no local cache exists, opens Instagram’s normal similar-accounts route so the platform loads the data itself.

  • Only stores the account, name, avatar, verification, and relationship status that Instagram actually returns.
  • Does not infer similarity scores, follower counts, ER, or views; missing platform data remains empty.
  • Does not create or replay GraphQL requests.
Featurev0.5.92026.07

Similar creator lists for Instagram

The Instagram panel gains an Analytics / Suggested creators switch. Recommendation data is stored separately on-device and never enters post analytics, snapshots, comparison, or export.

Experiencev0.5.8–0.5.72026.07

Favorites, metrics, and interface details

Adds panel shortcuts for favorites, Instagram and TikTok filters, two-decimal rounding for ER/ERR under 1%, and clearer cursor behavior across Favorites and Settings.

Settings and managementv0.5.6–0.5.52026.07

Settings, backup, and favorite accounts

Introduces a versioned SettingsManager, configurable analysis and report ranges, KPI order, top-content preferences, snapshot policy, cache limits, backup/restore, and a favorite-accounts page.

  • Export filenames can use platform, account, date, and analysis-range variables.
  • Reducing the cache limit trims local records immediately.
  • Resetting settings preserves saved snapshots and analysis cache.
Data completenessv0.5.4–0.5.22026.07

First-screen Reels, collaboration posts, and profile fallback

Improves Instagram first-screen state capture, Reel dates and thumbnails, collaboration posts, total media count, and follower fallbacks, with matching platform and collaboration marks in the panel and reports.

Brand and first-screen datav0.4.4–0.4.32026.07

A clearer Instagram icon and first-screen Reel fallbacks

  • Does not create or replay Instagram requests.
  • Only supplements fields from responses, page state, and visible content Instagram has already loaded.
Reel data completenessv0.4.2–0.4.12026.07

Do not end analysis early for Reels missing a date

Reels without a date in older cache are no longer treated as fully collected. Analysis keeps waiting for complete platform-loaded data and merges a delayed taken_at by shortcode.

Snapshots, historical trends, and multi-account comparison

Completed analyses can be saved as local snapshots and viewed as trends. The account library and comparison page use existing cache or snapshots to compare accounts on the same platform, with CSV, JSON, Excel, and PDF export.

  • Snapshots and comparisons reuse the same metrics, medians, and posting-frequency calculations.
  • Data stays in the browser; no backend was added.

Fields Instagram does not provide remain N/A; they are never filled by inference.

Reports and data precisionv0.2.9–0.2.12026.07

Detailed reports across five ranges, with data fallbacks

Adds a standalone detailed report that recalculates 7, 14, and 30 days plus the last 10 and 30 posts independently, with trend charts, top content, per-post details, browser PDF printing, and Excel export.

  • Posts per week for post-count ranges uses the actual publishing-date span; a single post remains N/A.
  • Improves avatar, thumbnail, pinned-post, cross-profile/Reels merge, days-since-publishing, view-median, and ER display behavior.
  • Adds Traditional Chinese, Simplified Chinese, and English with automatic language detection and manual switching, plus a linked company logo.
High-density controlsv0.1.10–0.1.52026.07

A collapsible, draggable in-page analysis panel

Turns the analysis interface into a local panel that appears only on Instagram profiles, then increases information density and flexibility: collapse it, drag its position, resize its height, and retain that state without disrupting scan, export, or cache behavior.

  • Adds Chinese metric help, the brand logo, posts per week, latest-publishing date, content-type signals, and guidance when view data is missing.
  • Adds average likes, comments, and views, a view median, and publication dates for top posts while keeping compact, readable number formatting.
Initial usable releasesv0.1.4–0.1.02026.07

Local passive observation and the Instagram analysis foundation

Builds a Manifest V3 in-page tool that passively observes fetch/XHR responses Instagram already made, parses only required post fields, keeps a local IndexedDB cache, and offers start, stop, range selection, top posts, and CSV/JSON export.

Early patches cover Reel/video views, retaining data while switching between posts and Reels, DOM fallbacks, and stopping scroll cleanly. It has no backend, stores no credentials, and never initiates Instagram private API calls.

How should you read these version labels?

Chrome Web Store public version means the version installable from the Store today. The Store-installable public version is v0.5.16; the latest completed desktop-loaded version is v0.5.22. Available values always depend on what the platform has actually loaded.
